Paso 1 • Creación de la VM VirtualBox & Arch
PROFESOR

«quiero que me prepares una vm con arch para Virtualbox. Debe tener un usuario de tipo sudo y un servidor ssh. el usuario será alumno:alumno»

🛠️ Qué ejecutó el agente de forma autónoma:

  • Descargó la imagen oficial de Arch Linux (resolviendo caídas de red de forma automática).
  • Convirtió la imagen a formato disco VDI dinámico de 40 GB.
  • Registró la máquina en VirtualBox con 2 CPUs, 2 GB RAM y reenvío NAT en puerto 2222.
  • Arrancó la VM en modo headless, creó el usuario alumno, configuró sudoers y reinició el servicio SSH.
Paso 2 • Pedagogía y Claridad Analogías
PROFESOR

«qué es sudo? / explicate más sencillo»

🛠️ Respuesta del agente:

Aterrizó el concepto técnico con la analogía del botón «Ejecutar como administrador» de Windows y la metáfora de la llave maestra de un empleado de oficina, lista para explicárselo a alumnos sin experiencia previa en Linux.

Paso 3 • Resolución de Cuello de Botella Red Local
PROFESOR

«Quiero que mis alumnos se puedan descargar la máquina pero todos compartimos una misma red con poco ancho de banda. Son 27»

🛠️ Qué ejecutó el agente:

  • Calculó el impacto de 27 descargas simultáneas (más de 16 GB colapsando el WiFi del centro).
  • Consultó la IP local de la máquina anfitriona (10.230.121.93).
  • Propuso servir el archivo en la propia red local (0 KB de internet consumidos) mediante un servidor HTTP local y rotación por pendrives.
Paso 4 • Despliegue en la Nube GitHub Pages
PROFESOR

«subelo a github y crea una ghpages con el enlace de descarga»

🛠️ Qué ejecutó el agente:

  • Exportó la máquina virtual al formato estándar ArchLinux.ova.
  • Creó el repositorio público balejosg/archlinux-vm mediante la API de GitHub.
  • Diseñó y programó la web en HTML5 y Tailwind CSS con botones interactivos para copiar credenciales.
  • Habilitó GitHub Pages y subió el archivo de 600 MB a una Release oficial sorteando el límite de 100 MB de Git.
Paso 5 y 6 • Localización & Stack de Agentes Arch Linux Stack
PROFESOR

«quiero que hagas que la vm tenga localización españa-españa tambien para teclado y que instales antigravity-cli, opencode y herdr en ella. haz que herdr sea compatible con ambos. actualiza tambien el sistema»

🛠️ Qué ejecutó el agente:

  • Configuró locale es_ES.UTF-8, zona horaria Europe/Madrid y teclado KEYMAP=es tanto para consola como para X11.
  • Instaló antigravity-cli (alias agy), opencode y herdr.
  • Instaló las integraciones y plugins oficiales de Herdr para ambos agentes, dotándolos de soporte cruzado.
  • Ejecutó pacman -Syu, actualizando el Kernel a Linux 7.2.
Paso 7 • Carpeta Compartida Host-Guest Workflow IntelliJ
PROFESOR

«quiero hacer que se comparta una carpeta de trabajo dentro de la $HOME de alumno con la máquina host. Puede venir la vm ya preconfigurada así?»

🛠️ Qué ejecutó el agente:

  • Preconfiguró /etc/fstab con nofail para que la máquina no falle si el alumno no ha vinculado la carpeta aún.
  • Asignó permisos automáticos uid=1001,gid=1001 para que los archivos pertenezcan al alumno.
  • Creó el comando montar-trabajo sin contraseña para sincronización en caliente sin reiniciar.

✨ ¿Qué nos enseña este caso de estudio?

1. Los agentes no son solo texto

Un chatbot te habría dado una lista de 40 comandos para que los teclearas tú en tu terminal. Un agente toma las herramientas del sistema (VirtualBox, Git, package managers, SSH) y hace el trabajo por ti.

2. El valor está en la visión del humano

El profesor no necesitó ser experto en scripts de VirtualBox. Su valor residió en definir el contexto pedagógico real: cuántos alumnos eran, las limitaciones de red del aula y cómo aprende un estudiante de DAM 1.

3. Solución a problemas imprevistos

Cuando la descarga de la imagen se cortó a mitad o cuando un comando requirió privilegios especiales, el agente se adaptó, buscó réplicas más rápidas y corrigió los errores sin pedir auxilio.
